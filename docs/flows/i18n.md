# Flujo: i18n (textos y traducciones)

Cómo se añade un texto, cómo se traduce y qué garantiza que nada quede sin traducir. El **contrato** está en [`2026-10-26-i18n-operativa.md`](../superpowers/specs/2026-10-26-i18n-operativa.md); aquí, el **quién y cuándo**.

## Principio

**El texto en inglés es la clave.** Se escribe `t("Prices")`; si hay traducción se muestra `"Precios"`, si no, `"Prices"`. Nunca se ve una clave críptica ni un hueco vacío.

**La fuente de verdad está en el repo**, no en la base de datos:

```
packages/i18n/catalog.en.json   # todas las cadenas en inglés del Core
packages/i18n/locales/<locale>.json   # mapa "Prices" → "Precios" (8 ficheros: todos menos en)
packages/<module>/locales/<locale>.json  # cadenas del módulo
```

La base de datos (`translations`) es un **espejo sembrado** desde estos ficheros; se usa en runtime y permite ediciones del admin.

## Quién hace qué

| Paso | Ejecuta | Revisa / verifica |
|---|---|---|
| 1. Escribir el texto en inglés (legible, autocontenido, con `{placeholders}` si hay datos) | Implementador | Revisor de estilo: nada de claves crípticas ni texto ambiguo ("Sort order" ≠ "Place order") |
| 2. Actualizar el catálogo: `pnpm i18n:scan` y **commitear** el resultado | Implementador | CI: el catálogo no puede estar desactualizado |
| 3. Traducir los **8 locales no base**: PR que rellena `locales/*.json` | **Traductor** | CI (`i18n:check`): claves y placeholders idénticos; el orquestador revisa sentido y tono |
| 4. Sembrar en la instancia (migración del Core / instalación del módulo) | Orquestador (despliegue) | Idempotente por `(locale, text_hash)`; prioridad **`manual > import > code > module`**: el Core manda en sus cadenas |
| 5. Editar/importar en caliente si hace falta (sin PR) | Admin de la instancia (panel) | `source: manual`/`import`; se conserva al reinstalar módulos; validación en la puerta (longitud, placeholders, texto plano) |
| 6. Ver cobertura y faltantes | Admin (`/translations/status`) / panel | Por locale: % traducido y lista de faltantes |

**Reglas del Traductor** (agente): **solo abre PRs** (nunca escribe en BD); **nunca** cambia el inglés (es la clave); conserva los `{placeholders}` **exactos**; no traduce nombres de marca; mantiene el formato y el orden del fichero.

## CI: lo que falla el build

`pnpm i18n:check` (job `admin`) falla si:

- una cadena del catálogo **falta** en algún locale del set;
- un locale tiene una cadena que **no** está en el catálogo (sobrante);
- los **placeholders** de una traducción no coinciden con el inglés;
- un fichero de locale es **JSON inválido**;
- el **catálogo está desactualizado** respecto al código (hay que correr `i18n:scan`).

**El check valida los 9 locales del set**, aunque una instancia concreta sirva solo algunos (`localization.enabled_locales`). El código debe poder servirlos todos.

## Idiomas por instancia

- **Disponible** = los 9 del código; **habilitado** = los que sirve la instancia (`en` no se puede deshabilitar). Se siembran **siempre los 9**, así habilitar un idioma después no exige re-sembrar.
- Quien instala habilita/deshabilita en el wizard o en Ajustes → Localización; los deshabilitados **no se sirven**.
- Un locale habilitado con menos del 100 % **no rompe** la app: cae a inglés.

Cambiar `localization.default_locale` en `/settings` **no** reescribe la cookie
`027_locale` ni el panel del usuario actual: el valor guardado solo se aplica a
**perfiles nuevos** (canje de invitación) y a los clientes que lean
`settings_public`. Los perfiles existentes conservan su preferencia.

## Idioma de la interfaz del wizard y la ayuda

El wizard (`/setup`) y la página pública `/help/firebase` eligen su idioma de
interfaz de forma **independiente** de `localization.default_locale`:

- Cookie `027_locale`: `Path=/`, `SameSite=Lax`, `Max-Age=1 año`. **No es
  `HttpOnly`** porque la escribe el cliente, y **no es una cookie de sesión**:
  no contiene identidad, tokens ni secretos.
- Precedencia: `?lang` (solo en la ayuda, para enlaces compartidos) → cookie →
  `en`.
- El valor se valida contra los 9 locales: un `?lang` inválido se ignora y se
  comprueba la cookie; si no hay ninguno válido, cae a `en`. Nunca se refleja
  texto arbitrario en la página.
- El selector del wizard escribe la cookie y refresca; el de la ayuda actualiza
  además `?lang` para que el enlace sea compartible.
- Al llegar a Preferences, el idioma del wizard se **propone** como
  `localization.default_locale` si el valor guardado es el de semilla (`en`) o
  está vacío. No se guarda automáticamente: el instalador lo confirma con el
  resto del formulario y puede cambiarlo.
- El panel privado usa la misma cookie `027_locale`. Su base son los
  diccionarios empaquetados del repo y superpone las filas de `translations`
  (ediciones en runtime): la tabla puede estar vacía y los 9 locales se sirven
  igualmente.

## Runtime

- El cliente pide `GET /api/v1/translations?locale=xx` (autenticado; solo locales habilitados) y recibe el mapa `text_en → traducción` **resuelto con fallback**, con **`ETag` del cuerpo servido**: si una traducción se edita, el ETag cambia; si no cambió, `304`.
- El **servidor no localiza** (ADR 0007): devuelve los pares; quien pinta el texto es el cliente.
- Los **errores** usan el mismo mecanismo: el `code` lleva un mensaje por defecto en inglés, y **ese texto es la clave** del catálogo (nunca `error.<code>`).

## Módulos

1. El módulo trae `locales/*.json` y su catálogo inglés en su paquete (subconjunto de los 9, con `en`).
2. Al instalarlo, se siembra con `source: module:<key>`.
3. Un módulo **no puede pisar** una cadena del Core: si su inglés coincide con una existente de `code`/`import`/`manual`, **no se siembra** y queda aviso. Al desinstalar, se borran sus filas (task-03); las `manual` se conservan.
4. El mismo `i18n:check` cubre los locales del módulo.

## Criterio de cierre

Un cambio con textos está cerrado cuando: el catálogo está actualizado (`i18n:scan` commiteado), los **8 locales + catálogo** tienen todas las claves con placeholders idénticos (`i18n:check` en verde), y —si aplica— el módulo tiene sus locales en el paquete. Con esos tres, ningún texto puede quedar sin traducir sin que el build lo diga.
