# Setup i18n and Firebase Help Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a persisted language selector to the setup wizard and a public, localized Firebase help page opened from the notifications section.

**Architecture:** The wizard and help page read `027_locale` (query `?lang` wins on the help page), load dictionaries straight from `packages/i18n/locales/*.json`, and render through `t()` with `{param}` interpolation. A client `LocaleSwitcher` writes the cookie and refreshes; the help page is public and the proxy skips Supabase for `/help/*`. The chosen wizard language is proposed as `localization.default_locale` on arrival at Preferences, never saved automatically.

**Tech Stack:** Next.js 16 App Router (server/client components, Cache Components), React 19, TypeScript, Vitest, Supabase, `@027apps/i18n`.

**Spec:** `docs/superpowers/specs/2026-11-06-setup-i18n-help-design.md`

## Global Constraints

- Code, comments, commits, branches and GitHub surface in **English**; internal docs and conversation in **Spanish**.
- English text is the i18n key; every translatable string is a **literal** `t("...")` call. All 9 locales must be complete and placeholders identical (`i18n:check`).
- `027_locale` is **not** a session cookie: `Path=/`, `SameSite=Lax`, `Max-Age=31536000`, **not HttpOnly**, no identity or secrets; validate against the 9 supported locales.
- Do **not** read cookies in `apps/admin/src/app/layout.tsx`; it would make every route dynamic. The wizard/help set `document.documentElement.lang` in a client component.
- `/help/*` must work without Supabase env vars and without a session; keep the CSP generated by the proxy.
- Colors only through semantic tokens; no hardcoded palette classes. No `any`. No `console.log`.
- Before claiming done: `pnpm lint`, `pnpm tsc`, `pnpm test`, `pnpm i18n:check`, `pnpm --filter admin build`.
- One PR for this task, branched from `main`; no merge without explicit user order.
- Branch and task setup happen before Task 1: create `docs/tasks/sprint-web/task-02.md` (`estado: en curso`), branch `feature/setup-i18n-help` from `main`, and keep the pending sprint-06 follow-ups out of this branch.

## Review Focus

- **Hostile locale value:** a cookie or `?lang` containing HTML/script text must fall back to `en` and never be reflected.
- **Language change mid-wizard:** switching language must keep the current step and not wipe typed form values.
- **Help without Supabase:** `/help/firebase` must render 200 with Supabase unset or unreachable; it is the guide for exactly that situation.
- **Default locale proposal:** a previously saved non-seed `default_locale` must not be overwritten by the wizard language.
- **Interpolation safety:** strings without params and literal braces must be untouched; missing params leave the placeholder rather than rendering `undefined`.
