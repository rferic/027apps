App Web Panel Decisiones

App Android

El miembro vive aquí: ve su cuota, enseña el QR, copia un enlace, revoca y pide plazas. El administrador ve las solicitudes, pero las gestiona en el panel.

Web pública

El canje funciona sin app. El GET de /join/[code] solo pinta; el botón «Continuar» es el que canjea, para que un prefetch no gaste el QR.

Panel de administración

Configurar niveles, resolver solicitudes, ver el árbol y entender el origen de cada invitación. El contador de solicitudes se refresca por polling.

Decisiones que este mockup fija

  • Dos puertas, una invitación: el QR crea una invitación de 15 min; el enlace dura 48 h. La cuota se gasta al canjear, no al enseñar el QR.
  • El GET de /join/[code] no canjea: hay un botón «Continuar» para que un prefetch de WhatsApp no se coma el código.
  • La barra es ocupación viva: usadas + reservadas / base + concedidas. Una cuenta desactivada ocupa; una purgada libera.
  • La solicitud no cambia el nivel: suma plazas permanentes y revocables a esa persona.
  • El panel no tiene realtime nuevo: el contador de Solicitudes se refresca por polling.
  • La app no aprueba: solo lista y abre el panel. La gestión es del panel.
  • El push es genérico: «Nueva solicitud de invitación», sin importes ni nombres; el detalle está al abrir.

Fuera de este mockup

  • El flujo de login, el shell de módulos y el canje con cuenta existente ya existentes (solo se muestran sus variantes nuevas).
  • La pantalla de descarga del APK y el wizard de la app; el canje web reutiliza el del sprint 16.
  • Notificaciones push en iOS y la aprobación desde la app.
